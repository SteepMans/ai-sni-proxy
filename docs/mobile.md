# Телефон: Incy и Happ

На телефоне нет файла `hosts`, который правит клиент для компьютера. Зато у
Xray-клиентов [Incy](https://docs.incy.cc/en/routing/) и
[Happ](https://www.happ.su/main/dev-docs/routing) есть профили маршрутизации, и
в профиле можно задать то же самое: имена из списка указывают на наш вход и
идут к нему напрямую, а не через VPN-сервер клиента.

Профиль лежит в папке [`mobile`](../mobile):

| Файл | Что это |
|---|---|
| `incy-link.txt` | ссылка `incy://routing/add/...` для Incy |
| `happ-link.txt` | ссылка `happ://routing/add/...` для Happ |
| `routing-profile.json` | сам профиль, чтобы посмотреть, что внутри |

## Как поставить

1. Откройте на телефоне `incy-link.txt` или `happ-link.txt` в режиме Raw и
   скопируйте строку целиком. Она длинная, около 90 тысяч символов: внутри
   весь список доменов.
2. **Incy:** добавьте профиль маршрутизации из буфера обмена (в настройках
   туннеля, раздел профилей маршрутизации) и сделайте активным профиль
   `ai-sni-proxy`.
3. **Happ:** то же самое, затем переподключитесь. Happ применяет смену профиля
   только после переподключения.

Активным может быть только один профиль, поэтому `ai-sni-proxy` заменит тот,
что стоял раньше. Остальной трафик, как и в стандартном профиле, идёт через
ваш VPN-сервер (`GlobalProxy: true`). Если в прежнем профиле были свои правила,
например российские сайты напрямую, перенесите их в `routing-profile.json` и
соберите ссылку заново (см. ниже).

## Как проверить

Откройте в браузере телефона <https://claude.ai/cdn-cgi/trace>. В строке `ip=`
должен быть не ваш адрес и не адрес вашего VPN-сервера, а в `loc=` не `RU`.

Если там ваш адрес, клиент для прямых соединений резолвит имя заново и обходит
`DnsHosts`. Если там адрес IPv6 — телефон ходит мимо подмены по IPv6. В обоих
случаях напишите [issue](https://github.com/SteepMans/ai-sni-proxy/issues) с
названием и версией клиента.

## Как собрать заново

Список доменов меняется, профиль собирается из него скриптом:

```sh
./mobile/build-profile.sh            # опубликованный список
./mobile/build-profile.sh --bundled  # domains/fallback.txt, без сети
```

Нужны `sh`, `awk`, `base64` и `curl` или `wget`. Профиль с тем же именем при
повторном импорте перезаписывается, удалять старый не нужно.

## Что внутри

- `DnsHosts` — каждое имя из списка отвечает адресом входа, как строка в `hosts`.
- `DirectSites` — те же имена с префиксом `full:`: только точное совпадение,
  поддомены, которых нет в списке, идут как обычно.
- `DirectIp` — адрес входа и локальные сети напрямую.
- `FakeDNS: false` — иначе клиент подменит адреса своими и `DnsHosts` не сработает.
